== Overview

Completed Phase 2 migration of ContentEditor from Qt WebEngineView to QTextEdit/QPlainTextEdit for content authoring. This follows the content rendering architecture migration decision.

== Phase 2.1: Update ContentEditor Header

**Status:** ✅ Complete

**Changes:**
* Replaced `#include <QWebEngineView>` with `#include <QTextEdit>` and `#include <QPlainTextEdit>`

  * `insertList(bool ordered)`
  * `insertLink(const QString& url)`
  * `insertImage(const QString& path)`
* Removed async content caching (QTextEdit is synchronous)
* Updated class documentation

== Phase 2.2: Update ContentEditor Implementation

**Status:** ✅ Complete

**Changes:**
* Removed all WebEngine includes and dependencies
* Replaced `QWebEngineView` with `QTextEdit` (WYSIWYG) and `QPlainTextEdit` (HTML source)
* Used `QStackedWidget` to toggle between editors
* Implemented rich text formatting using `QTextCursor` and `QTextCharFormat`
* Implemented all formatting methods using Qt's rich text framework
* Updated `loadContent()` to use `QTextEdit::setHtml()` (synchronous)
* Updated `getContent()` to use `QTextEdit::toHtml()` (synchronous, no caching needed)
* Updated `setHtmlMode()` to toggle between `QTextEdit` and `QPlainTextEdit`
* Updated `setPreviewMode()` to use `setReadOnly()`
* Removed async JavaScript execution and content caching
* Implemented form marker insertion using `QTextCursor::insertHtml()`
* Added content synchronization between WYSIWYG and HTML modes

**Key Implementation Details:**
* `QStackedWidget` manages switching between WYSIWYG and HTML editors
* `syncContentBetweenModes()` ensures content is preserved when switching modes
* All formatting operations use `QTextCursor` and format objects
* Undo/redo support via `QTextEdit::undo()`/`redo()`

== Benefits of QTextEdit Migration

**Performance:**
* ✅ Synchronous content operations (no async overhead)
* ✅ Faster content loading and saving
* ✅ No JavaScript execution overhead

**Simplicity:**
* ✅ Native Qt widgets (no WebEngine dependency)
* ✅ Direct API access (no JavaScript bridge needed)
* ✅ Simpler codebase (removed ~200 lines of JavaScript)

**Reliability:**
* ✅ No WebEngine background thread issues
* ✅ Predictable behavior (synchronous operations)
* ✅ Better error handling
