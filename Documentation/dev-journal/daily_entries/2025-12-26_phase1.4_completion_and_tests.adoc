=== Window State Persistence Implementation

**File:** `reader/src/ReaderViewWindow.cpp`, `common/src/database/LocalDBManager.cpp`

Implemented window state persistence and restoration:

* **Window State Persistence (FR-2.1.3)**
  * `saveWindowState()` - Saves window geometry and state
  * Saves: `window_width`, `window_height`, `window_x`, `window_y`, `is_maximized`
  * Stores in `Local_Window_State` table
  * Atomic transaction with reading position

* **Window State Restoration (FR-2.1.4)**
  * `restoreWindowState()` - Restores window geometry and state
  * Validates geometry against screen bounds
  * Falls back to default geometry if invalid
  * Restores maximized state

* **Reading Position Persistence (FR-2.8.6)**
  * Saves: `page_id`, `anchor_id`, `scroll_position`
  * Stores in `Local_Reading_Position` table
  * Restores reading position on window open

* **Database Schema Updates**
  * Added `Local_Window_State` table to `LocalDBManager`
  * Added `Local_Reading_Position` table to `LocalDBManager`
  * Foreign key constraints to `Local_Library_Manifest`
  * Indexes for performance

=== Test Environment Fixes

**Segfault Resolution**

**Problem:** Test executables were crashing with segfaults (exit code 139) during cleanup.

**Root Cause:**
* Static `QApplication` instances in `initTestCase()` conflicted with `QTEST_MAIN`
* Double initialization of `QApplication` caused segfault during cleanup
* `ConsentDialog` parent handling issues in some environments

**Solution:**
* Removed static `QApplication` from `initTestCase()` methods
* Tests now use `QTEST_MAIN` or custom `main()` that creates `QApplication`
* Improved `ConsentDialog` parent handling in `WebChannelBridge`
* All tests now clean up properly without segfaults

**Files Fixed:**
* `test/unit/test_webchannelbridge.cpp`
* `test/unit/test_readerview_content.cpp`
* `reader/src/WebChannelBridge.cpp` (ConsentDialog parent handling)

== Technical Challenges

=== Filename Validation Security

**Problem:** Sandbox file operations needed to prevent directory traversal attacks.

**Solution:**
* Added filename validation in `WebChannelBridge::saveSandboxFile()`
* Validates original filename before sanitizing
* Rejects filenames containing `..` or `/` or `\`
* Uses `QFileInfo::fileName()` to sanitize filename
* Ensures files stay within sandbox directory

=== Database Connection Management in Tests

**Problem:** Tests were experiencing database connection issues and segfaults.

**Solution:**
* Removed conflicting `QApplication` instances
* Used proper test lifecycle management
* Ensured all database connections are properly closed
* Added proper cleanup in test teardown
