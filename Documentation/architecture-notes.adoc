== Content Rendering Architecture

=== Current Implementation: QTextDocument + Qt Quick/QML

**Status:** ✅ **IMPLEMENTED** (as of 2025-12-27)

The current implementation uses **QTextDocument/QTextBrowser** for content rendering and **Qt Quick/QML** for embedded applications. This architecture provides:

* HTML4 + CSS 2.1 content rendering (via QTextBrowser)
* QML embedded application support (via QQuickWidget)
* Qt Widgets form rendering (via FormEmbeddedWidget)
* WYSIWYG editing capabilities in Creator Tool (via QTextEdit)
* Synchronous rendering (no flash on theme changes)
* Native Qt integration (no Chromium dependency)

=== Architecture Decision

**Decision Date:** 2025-12-26

**Decision:** Migrated from Qt WebEngine to QTextDocument + Qt Quick/QML architecture.

**Rationale:**

1. **Rendering Flash Issue:** Qt WebEngine's theme change rendering flash was unacceptable and unfixable due to multi-process architecture
2. **QML Alternative:** Qt Quick/QML provides equivalent functionality to JavaScript SPAs for embedded applications
3. **Form System:** Qt Widgets provides robust form rendering and validation capabilities
4. **Simpler Deployment:** No Chromium dependency reduces deployment complexity
5. **Better Performance:** Native Qt rendering is more efficient for text-heavy content

**See:** `content-rendering-decision-analysis.adoc` and `2025-12-26_content_rendering_architecture_decision.adoc` for detailed analysis.

=== Implementation Details

==== Content Rendering (Reader)

**Component:** `ReaderView` (`reader/src/ui/ReaderView.cpp`)

* Uses `QTextBrowser` for HTML content rendering
* Supports HTML4 + CSS 2.1 subset
* Theme-aware palette-based styling (no flash on theme changes)
* Parses content for QML app markers and form markers
* Embeds `QmlEmbeddedAppWidget` and `FormEmbeddedWidget` instances

**Content Parser:** `ContentParser` (`reader/src/ContentParser.cpp`)

* Parses HTML for QML app markers: `<div data-smartbook-qml-app="app_id"></div>`
* Parses HTML for form markers: `<div data-smartbook-form="form_id"></div>`
* Cleans HTML to remove markers before rendering

==== Embedded Applications

**Component:** `QmlEmbeddedAppWidget` (`reader/src/ui/QmlEmbeddedAppWidget.cpp`)

* Uses `QQuickWidget` to embed QML applications
* Loads QML code from `Embedded_Apps` table (`qml_code` column)
* Provides `QmlAppBridge` for C++/QML communication
* Supports sandbox file system access
* Supports form data persistence

**Bridge:** `QmlAppBridge` (`reader/src/QmlAppBridge.cpp`)

* C++/QML communication bridge
* Registered as QML type "SmartbookBridge"
* Provides methods: `saveFormData`, `loadFormData`, `saveSandboxFile`, `loadSandboxFile`, etc.

==== Form Rendering

**Component:** `FormEmbeddedWidget` (`reader/src/ui/FormEmbeddedWidget.cpp`)

* Uses Qt Widgets for form rendering
* Generates forms from JSON schemas (via `FormSchemaParser`)
* Validates form data (via `FormValidator`)
* Persists form data to cartridge database
* Theme-aware styling

**Form System Components:**

* `FormSchemaParser` - Parses JSON form schemas
* `FormWidgetGenerator` - Generates Qt Widget form layouts
* `FormValidator` - Validates form data against schemas
* `FormDataSerializer` - Serializes/deserializes form data

==== Content Editor (Creator Tool)

**Component:** `ContentEditor` (`creator/src/ContentEditor.cpp`)

* Uses `QTextEdit` for WYSIWYG editing
* Uses `QPlainTextEdit` for HTML source editing
* Supports rich text formatting (bold, italic, underline, colors, fonts, lists, links, images)
* Synchronous content access (no JavaScript bridge needed)

=== Limitations and Trade-offs

**HTML/CSS Support:**

* Limited to HTML4 + CSS 2.1 subset
* No HTML5 features (semantic elements, canvas, video, audio)
* No CSS3 features (flexbox, grid, transforms, animations)
* No JavaScript execution in content

**Embedded Applications:**

* Must use QML instead of JavaScript SPAs
* Requires QML knowledge for app development
* No direct HTML/CSS/JavaScript app support

**Forms:**

* Must use Qt Widgets (no HTML forms)
* JSON schema-based form definitions
* No JavaScript form validation (uses C++ validation)
