== Overview

This document provides a detailed implementation plan for migrating from Qt WebEngine to QTextDocument + Qt Quick/QML architecture for content rendering in SmartBook.

**Decision:** Use QTextDocument/QTextBrowser for content rendering and Qt Quick/QML for embedded applications.

**Rationale:** See `content-rendering-decision-analysis.adoc` and `2025-12-26_content_rendering_architecture_decision.adoc`.

== Implementation Phases

=== Phase 1: Reader View Migration (QTextBrowser)

**Goal:** Replace `QWebEngineView` with `QTextBrowser` in `ReaderView`.

==== 1.1 Update ReaderView Header

**File:** `reader/include/smartbook/reader/ui/ReaderView.h`

**Changes:**
* Replace `#include <QWebEngineView>` with `#include <QTextBrowser>`
* Replace `QWebEngineView* m_webView;` with `QTextBrowser* m_textBrowser;`
* Remove `WebChannelBridge* m_webChannelBridge;` (will be replaced with QML bridge)
* Update class documentation

==== 1.2 Update ReaderView Implementation

**File:** `reader/src/ui/ReaderView.cpp`

**Changes:**
* Remove WebEngine includes (`QWebEngineView`, `QWebEngineProfile`, `QWebEngineSettings`, `QWebEnginePage`, `QWebChannel`)
* Add `#include <QTextBrowser>`
* Replace `QWebEngineView` instantiation with `QTextBrowser`
* Remove `setupWebEngine()` method
* Update `loadContentFromDatabase()`:
  * Remove WebChannel setup
  * Use `QTextBrowser::setHtml()` instead of `QWebEngineView::setHtml()`
  * Remove `onLoadFinished()` slot (QTextBrowser loads synchronously)
* Update `buildHtmlDocument()`:
  * Ensure HTML is HTML4 compliant
  * Remove HTML5/CSS3 features if present
* Update `applySettingsToHtml()`:
  * Use CSS 2.1 compatible properties only
  * Remove CSS3 variables (use direct CSS properties)
* Emit `contentLoaded()` signal immediately after `setHtml()` (synchronous)

**File:** `reader/src/ui/QmlEmbeddedAppWidget.cpp`

==== 1.4 Content Parser for QML Embedding

**New Component:** `ContentParser`

**File:** `reader/include/smartbook/reader/ContentParser.h`

**Purpose:** Parse HTML content and replace QML app markers with `QmlEmbeddedAppWidget` instances.

**Implementation:**
* Parse HTML content for QML app markers (e.g., `<div data-smartbook-qml-app="app_id"></div>`)
* Query `Embedded_Apps` table for QML code
* Replace markers with `QmlEmbeddedAppWidget` instances
* Maintain layout structure

**File:** `reader/src/ContentParser.cpp`

**Approach:**
* Use `QTextDocument` to parse HTML
* Find QML app markers in document structure
* Create `QmlEmbeddedAppWidget` for each marker
* Insert widgets into layout (requires custom layout or `QTextBrowser` subclass)

**Alternative Approach:**
* Use `QTextBrowser` subclass that supports embedded widgets
* Override `paintEvent()` or use `QTextDocument::drawContents()` with widget embedding
* Or use `QTextBrowser` with `QTextDocumentFragment` and custom rendering

**Recommended Approach:**
* Create `QTextBrowser` subclass: `ContentBrowser`
* Override `setHtml()` to parse and extract QML app markers
* Create separate layout for QML widgets
* Use `QTextDocument::toHtml()` to get HTML without QML markers
* Display HTML in `QTextBrowser`
* Display QML widgets in overlay or adjacent layout

=== Phase 4: WebChannel Bridge Replacement

**Goal:** Replace `WebChannelBridge` with QML property binding and direct C++ signals/slots.

==== 4.1 QML Bridge for Embedded Apps

**New Component:** `QmlAppBridge`

**File:** `reader/include/smartbook/reader/QmlAppBridge.h`

**Purpose:** C++ object exposed to QML for app communication.

**File:** `reader/src/QmlAppBridge.cpp`

**Features:**
* Expose C++ methods/properties to QML via `QQmlContext`
* Methods:
  * `saveFormData(formId, dataJson)` - Save form data
  * `loadFormData(formId)` - Load form data
  * `requestAppConsent(appId)` - Request consent
  * `saveSandboxFile(filename, data)` - Save sandbox file
  * `loadSandboxFile(filename)` - Load sandbox file
  * `listSandboxFiles()` - List sandbox files
  * `deleteSandboxFile(filename)` - Delete sandbox file
  * `logMessage(level, message)` - Log message
* Properties:
  * `cartridgePath` - Current cartridge path
  * `cartridgeGuid` - Current cartridge GUID
* Signals:
  * `formDataSaved(formId, success, error)`
  * `formDataLoaded(formId, dataJson, error)`
  * `appConsentGranted(appId)`
  * `appConsentDenied(appId)`

**Usage in QML:**
```qml
import SmartBook 1.0

Item {
    property var bridge: SmartbookBridge
    
    function saveData() {
        bridge.saveFormData("form1", JSON.stringify(formData))
    }
    
    Connections {
        target: bridge
        function onFormDataSaved(formId, success, error) {
            if (success) {
                console.log("Data saved")
            }
        }
    }
}
```

== Risk Mitigation

=== Risk 1: QML Embedding Complexity

**Risk:** Embedding QML widgets in HTML content may be complex.

**Mitigation:**
* Use `QTextBrowser` subclass with custom layout
* Or use overlay approach (HTML in background, QML widgets on top)
* Proof of concept before full implementation

=== Risk 2: Form Widget Layout

**Risk:** Embedding form widgets in content layout may be challenging.

**Mitigation:**
* Similar approach to QML embedding
* Use `QTextBrowser` subclass or overlay
* Test with simple forms first

=== Risk 3: HTML4/CSS 2.1 Limitations

**Risk:** Content may not render as expected with limited CSS support.

**Mitigation:**
* Validate content during import
* Warn authors about unsupported features
* Provide HTML4/CSS 2.1 style guide

=== Risk 4: QML Learning Curve

**Risk:** Authors may prefer JavaScript over QML.

**Mitigation:**
* Provide comprehensive QML documentation
* Create QML app templates
* Provide migration guide from JavaScript to QML
